# Orbito

Нативное приложение для macOS 26+, которое управляет заданиями `launchd` (LaunchAgents). В нём можно просматривать задания, визуально менять расписание, создавать, запускать, включать и отключать, перезагружать и удалять задания, читать логи и видеть плановые запуски в календаре. Редактировать plist вручную и набирать команды `launchctl` больше не нужно.

Стек: Swift 6, SwiftUI + AppKit, Liquid Glass (`glassEffect`, `GlassEffectContainer`, `.glass` / `.glassProminent`). Сторонних зависимостей нет, интернет не нужен.

## Возможности

- **Обзор.** Сколько всего заданий, сколько загружено в launchd, сколько отключено и сколько с ошибками. Ниже — ближайшие плановые запуски, проблемные задания и избранное.
- **Задачи.** Список с поиском по Label, названию, пути и аргументам. Фильтры: все, загруженные, отключённые, с ошибками, с расписанием, без расписания. Сортировка по названию, следующему запуску или состоянию. Справа — карточка задания.
- **Редактор расписания.** Режимы: ежедневно (в том числе несколько раз в день), по дням недели, еженедельно, ежемесячно, каждый час, каждые N минут (`StartInterval`) и расширенный (произвольные записи `StartCalendarInterval` плюс `StartInterval`). Время выбирается на графических часах. Перед сохранением видны предпросмотр следующих запусков и фрагмент plist.
- **Мастер создания** из 5 шагов: основное → команда (можно перетащить скрипт) → расписание → логи → проверка с предпросмотром plist.
- **Управление:** запустить сейчас (`kickstart`), загрузить или выгрузить, перезагрузить, включить или отключить, редактировать, дублировать, удалить (в Корзину), показать в Finder, копировать команду, экспорт и импорт plist.
- **Просмотр логов** в отдельном окне: stdout/stderr, поиск, автообновление, автопрокрутка, копирование, последние N строк. Огромные файлы читаются с конца, а не целиком.
- **Календарь:** день, неделя, месяц. Учитывает местный часовой пояс и переход на летнее и зимнее время. Клик по событию открывает задание.
- **История** действий, выполненных Orbito, и ошибок, замеченных во время его работы.
- **Настройки:** тема, автообновление и его интервал, показ системных заданий, каталог резервных копий, число строк в логах, запуск при входе в систему, уведомления.
- **Меню в строке меню** с ближайшими запусками и быстрым запуском избранного. Горячие клавиши: ⌘N, ⌘R, ⇧⌘R, ⌘E, ⌥⌘R, ⇧⌘F, ⇧⌘I, ⌘1…⌘8. Контекстное меню по правому клику.

## Developer Mode

Включается в «Настройки → Developer» или в меню Developer (⌥⌘D). По умолчанию выключен — тогда интерфейс максимально простой. Изменения применяются сразу, без перезапуска.

- **CLI-подсказки.** При наведении на действие появляется popover с переключателем `macOS | Linux` (для Linux — ещё `systemd | cron`).
  - Вкладка macOS показывает точные команды `launchctl` / `plutil` для выбранного агента: его Label, домен, путь и изменённые ключи.
  - Вкладка Linux — справочник с пометкой **Reference Only**. Orbito эти команды не выполняет, и к заданиям на Mac они не относятся. Для действий без прямого аналога (например, «запустить запись cron сейчас») вместо команды объясняется разница. Расписание задания переводится в cron или `OnCalendar` только как «похожее», с оговорками.
- **Терминальные команды (Command Preview).** Подключение, платформа, планировщик, действие, изменения конфигурации, воспроизводимая последовательность команд, предупреждения, «Копировать всё».
- **Предпросмотр перед изменениями.** Любое изменяющее действие сначала показывает diff и команды, а выполняется только после подтверждения.
- **Dry Run.** Ничего не выполняется: команды записываются в Историю команд как «CLI-эквивалент».
- **Configuration Diff.** Структурный diff plist (key path: добавлено, удалено, изменено) и построчный XML (unified или side-by-side), «Copy Diff». Для изменения файла показываются ручные эквиваленты через `plutil -replace` / `-remove`.
- **Сырой plist и Advanced Editor.** Подсветка, копирование, «Показать в Finder». Правка проходит валидацию и проверку diff и сохраняется только после подтверждения. Простой просмотр никогда ничего не записывает.
- **История команд.** Время, задание, действие, команда, код выхода, stdout и stderr.
  - Типы записей: выполненная команда, операция с файлом, внутренняя операция, CLI-эквивалент.
  - Есть поиск, фильтры и очистка.
  - Секреты маскируются; хранится не больше 1000 записей.
- **CLI Inspector.** Только чтение: `launchctl print`, `blame`, `print-disabled`, `list`.
- **Расширенные логи.** Поток «launchd» (`launchctl print` + `log show` за последний час) и экспорт.

Архитектура описана в [docs/architecture/overview.md](docs/architecture/overview.md). Заметки о возможных удалённых подключениях (не реализованы) — в [docs/architecture/remote-connections.md](docs/architecture/remote-connections.md).

## Сборка и запуск

Нужен Xcode 26 или новее с принятой лицензией (`sudo xcodebuild -license accept`).

```bash
open Orbito.xcodeproj    # затем ⌘R в Xcode
```

Сборка из терминала:

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  xcodebuild -project Orbito.xcodeproj -scheme Orbito -derivedDataPath build/DerivedData build
open build/DerivedData/Build/Products/Debug/Orbito.app
```

Тесты используют Swift Testing и mock-реализацию launchctl, поэтому реальные задания они не трогают:

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  xcodebuild -project Orbito.xcodeproj -scheme Orbito -derivedDataPath build/DerivedData test
```

Приложение подписывается ad-hoc (`CODE_SIGN_IDENTITY = "-"`) с включённым Hardened Runtime. Для распространения укажите свой Developer ID Team и пройдите нотаризацию.

Отладочные аргументы запуска работают только в Debug:

```bash
open build/DerivedData/Build/Products/Debug/Orbito.app --args -OrbitoSection calendar
open build/DerivedData/Build/Products/Debug/Orbito.app --args -OrbitoSelect com.example.task -OrbitoSheet schedule
open build/DerivedData/Build/Products/Debug/Orbito.app --args -developerMode YES -OrbitoSelect com.example.task -OrbitoSheet preview
```

## Архитектура

```
Orbito/
├── App/          OrbitoApp (сцены, команды меню, MenuBarExtra), AppState (единый источник данных), AppSettings
├── Models/       PlistValue, LaunchJob/JobDefinition, Schedule (CalendarEntry, JobSchedule), ScheduleDraft,
│                 TaskStatus (домены, состояния), HistoryEvent
├── Services/     CommandRunner (Process, только массив аргументов), LaunchctlService (+ парсеры вывода),
│                 PlistService, LaunchAgentScanner (+ JobAnalyzer), ScheduleService (расчёт запусков, описания),
│                 JobOperations (бэкап → запись → plutil → launchctl → откат), BackupService / LabelValidator,
│                 LogService (чтение хвоста файла), Stores (история, метаданные), SystemIntegration
├── ViewModels/   TaskList, Dashboard, TaskEditor / ScheduleEditor, NewTask (мастер), LogViewer, Calendar
├── Views/        Dashboard, Tasks, Editor, Wizard, Calendar, Logs, History, Settings, MenuBar
└── Components/   GlassCard, StatusIndicator, SchedulePicker
OrbitoTests/      plist, расписания, расчёт запусков (включая DST), парсинг и ошибки launchctl,
                  операции и откат, Label, чтение логов
```

Бизнес-логика живёт в `Services` и `ViewModels`. Views только связывают данные с интерфейсом и вызывают действия.

## Работа с launchd

**Обнаружение.** Задания из `~/Library/LaunchAgents` можно редактировать. Задания из `/Library/LaunchAgents` и `/Library/LaunchDaemons` показываются, если это включено в настройках, и доступны только для чтения.

**Состояния не смешиваются.** Для каждого задания отдельно определяются:

1. Файл есть на диске.
2. Задание загружено в launchd (`launchctl list` или `launchctl print <domain>`).
3. Процесс сейчас выполняется (есть PID).
4. Задание отключено. Источник — база переопределений `launchctl print-disabled`, а если записи там нет, ключ `Disabled` в plist.
5. Чем закончился последний запуск: код выхода или сигнал.

Если состояние определить нельзя, показывается **Unknown**, а не успех. Ненулевой код последнего выхода — это предупреждение, а не доказательство, что задание сломано.

**Домены.** Агенты попадают в `gui/<uid>`, а при `LimitLoadToSessionType = Background` — в `user/<uid>`. Демоны — в `system`. Цель службы для команд записывается как `<domain>/<label>`.

**Команды.** Всегда запускаются через `Process` с `/bin/launchctl` и массивом аргументов. Shell, интерполяция строк и sudo не используются.

**Сохранение расписания:**

1. Проверка расписания.
2. Сравнение с файлом на диске. Если файл изменила другая программа, сохранение отменяется.
3. Резервная копия с меткой времени.
4. Атомарная запись с правами 0644 в исходном формате (XML или binary).
5. Проверка: файл заново декодируется и проходит `plutil -lint`.
6. Если задание было загружено — `bootout` и `bootstrap`. `bootstrap` повторяется, пока launchd завершает выгрузку старой версии.
7. Повторное сканирование и сообщение о результате.

При любой ошибке Orbito восстанавливает исходный plist и пытается снова загрузить старую версию. В сообщении честно сказано, удалось ли вернуть состояние launchd.

**Защитные проверки перед перезагрузкой, запуском и удалением:**

- **Чей это файл.** Через `launchctl print` Orbito проверяет, что служба загружена именно из этого plist. Если тот же Label загружен из другого файла (копия в Finder, системный агент), Orbito её не трогает.
- **Отключённые задания** не перезагружаются: launchd не загрузил бы их обратно.
- **Неизвестное состояние launchd.** Файл сохраняется, но задание не перезагружается. Результат помечается как частичный (оранжевый баннер, запись «не выполнено» в истории).
- **Тайм-аут `launchctl`** (30 с) — отдельная ошибка с пометкой «состояние неизвестно».
- **Одно действие на задание за раз.** Пока операция с заданием не закончилась, новые не запускаются.

Некорректные значения `StartInterval` и `StartCalendarInterval` (неверный тип, ноль) launchd всё равно игнорирует. Orbito сохраняет их как есть, пока пользователь не задаст корректное расписание.

**Меняются только ключи расписания.** Заменяются только `StartCalendarInterval` и `StartInterval`. Все остальные ключи, включая неизвестные Orbito и нераспознанные элементы массива, сохраняются. Форма записи (словарь или массив) тоже сохраняется.

**Новые файлы.** Пишутся во временный файл и переименовываются через `renamex_np(RENAME_EXCL)`. Это атомарно и никогда не перезаписывает существующий файл.

**Семантика расписаний** соответствует launchd, а не cron:

- пропущенное поле означает «любое значение»;
- `Weekday` 0 и 7 — воскресенье;
- если заданы и `Day`, и `Weekday`, задание срабатывает при совпадении любого из них.

Время следующего запуска считается в местном часовом поясе. Несуществующее при переходе на летнее время время пропускается, повторяющееся при переходе на зимнее срабатывает один раз. `StartInterval` отсчитывается от момента загрузки, поэтому на часы не проецируется. Все показанные времена — плановые: launchd не гарантирует запуск в точную секунду.

**Включение и отключение.** Используются `launchctl enable` и `launchctl disable` (постоянная запись в базе переопределений), а также отдельные действия «Загрузить» и «Выгрузить». «Отключено» и «не загружено» — разные состояния, интерфейс показывает оба.

**Запустить сейчас.** Выполняется `launchctl kickstart`. Если задание не загружено, Orbito предлагает сначала загрузить его. Если процесс уже работает, Orbito спрашивает разрешения перед `kickstart -k`.

**Удаление.** После подтверждения: `bootout`, резервная копия, перемещение файла в Корзину.

**История.** launchd не хранит историю запусков. Orbito записывает только свои действия и ошибки, которые заметил между обновлениями, пока был запущен.

## App Sandbox

Приложение распространяется **вне Mac App Store и без App Sandbox** (`ENABLE_APP_SANDBOX = NO`), с включённым Hardened Runtime. Причины:

1. Sandbox-процесс не может свободно писать в `~/Library/LaunchAgents`. Обходной путь — security-scoped bookmark от пользователя, но для каталога, которым приложение управляет постоянно, он ненадёжен.
2. `launchctl`, запущенный из sandbox-приложения, наследует песочницу и не может выполнять `bootstrap` и `bootout` в GUI-домене пользователя.
3. `SMAppService` регистрирует только агенты, вложенные в бандл приложения, а не произвольные plist пользователя, поэтому проблемы 1 и 2 он не решает.

Механизмы безопасности macOS (SIP и другие) не отключаются и не обходятся. Приватные API не используются, права root не запрашиваются. Системные каталоги доступны только для чтения — это проверяется и в интерфейсе, и в `JobOperations` (по пути к файлу).

## Ограничения

- Наблюдение за заданиями и уведомления работают, только пока Orbito запущен. Если закрыть окно, приложение продолжит работать через значок в строке меню.
- Календарь и обзор показывают только `StartCalendarInterval`. Задания с `StartInterval`, `KeepAlive`, `WatchPaths` и подобными ключами отображаются в списках, но на шкалу времени не попадают.
- Словари `KeepAlive` и другие сложные ключи сохраняются без изменений, но в Orbito не редактируются.
